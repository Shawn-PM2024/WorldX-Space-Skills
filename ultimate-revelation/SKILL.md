# Ultimate Revelation

## Overview

把低信息密度的长材料压缩为少数能改变理解、判断或行动的认知点。

把“可反溯”定义为：每条认知都能沿推导链回到足以支持它的原始事实或原话。页码、时间戳和段落号只帮助定位，不能代替原始内容。

遵循这一主链：

关键事实 → MECE 整理 → 抽象阶梯 → So What → 第一性原理

默认使用用户的语言输出。

## Core Principles

- 追求认知增量，不追求资料覆盖率。宁可保留 3 条强认知，也不要罗列 20 个主题。
- 先保存证据，再形成结论。不要先写漂亮观点，再回原文寻找装饰性引文。
- 把材料中的陈述、可观察事实、解释和推断分开。说话人的判断仍是“材料中的观点”，不是自动成立的外部事实。
- 让抽象保留向下解释力。删除人物、品牌和案例后，结论仍应能解释原始事实；向下检查时，也应能重新找到这些事实。
- 允许停在洞察层。材料不足以支持第一性原理时，标记“候选原则（推断）”或不输出原则。

## Prepare the Source

1. 读取完整相关材料后再形成全局结论。
2. 对录音、播客和视频，先获得尽可能完整的转写稿；保留说话人和时间信息（如已有），但不要把定位信息当成证据。
3. 对 PDF、网页、综述和报道，保留标题、表格、数字、引文归属及上下文。
4. 对明显的转写错误，做最小限度纠正并保留不确定性；不要把猜测出的词语当成关键事实。
5. 若材料超出可完整处理的范围，明确说明实际覆盖范围。不要用局部抽样冒充全文结论。

## Process Long Material in Three Passes

### Pass 1: Build an atomic fact ledger

按自然章节、话题或时间段分块阅读。只记录原子事实，不在每个分块内急于下最终结论。

为每条候选事实建立内部编号 F1、F2、F3：

- 保存最小充分的原始内容片段，通常是一句原话、一个数字、一个事件或一个明确对比。
- 保留必要上下文：谁在说、对象是什么、条件是什么。
- 区分事实类型：
  - 观察事实：材料可直接支持的事件、行为、数字或对比。
  - 材料陈述：说话人或作者提出的主张。
  - 案例：用于说明可能性，不能自动代表普遍规律。
  - 反证或边界：与主趋势冲突、限制外推或暴露不确定性的内容。
- 去掉寒暄、重复口癖和不改变含义的绕行，但不要丢掉少数关键例外。

### Pass 2: Form global structure

先去重，再用一个主要维度整理入选事实：

- 优先按机制、约束、因果阶段、问题—反应—结果或变化前后分组。
- 只有当任务关注不同立场时，才按说话人分组。
- 让每条事实只有一个主归属；需要时记录交叉关系，不复制成多个“证据”。
- 用可判断的类别名代替空泛主题名。例如使用“执行成本下降后，方向错误被放大”，不要只写“AI 能力”。
- 不为追求形式上的 MECE 强行消除现实中的重叠。显式保留例外与冲突。

形成 3–7 个候选事实簇 C1、C2、C3。每个事实簇都必须含有原始内容。

### Pass 3: Derive and reverse-audit insights

对每个事实簇依次完成下面五步。

#### 1. 关键事实

选择对结论不可替代的最小证据集。通常使用 2–4 条相互补充的事实；一条决定性事实也可以单独成立。

#### 2. MECE 整理

说明这些事实之间是并列、对比、递进、因果还是例外关系。不要把相同含义的重复发言误当成多份独立证据。

#### 3. 抽象阶梯

逐级上升：

原始内容 → 事实共性 → 稳定模式 → 机制或概念

每升一级都做一次向下检查：

- 这个抽象能解释哪些原始事实？
- 它是否抹掉了关键条件或反例？
- 如果换一组完全不同的事实，这句话是否仍然成立？若是，它可能过于通用。

在失去解释力之前停止上升。

#### 4. So What

把模式变成认知增量，回答至少一个问题：

- 它改变了我们对什么的理解？
- 它解释了哪种此前难以解释的现象？
- 它会改变什么判断、选择或行动？
- 它推翻了什么常见但较弱的说法？

避免“这说明很重要”“这反映一种趋势”等无信息增量的句子。

只有在材料支持时才写 Now What；不要为了给建议而越过证据。

#### 5. 第一性原理

寻找能够生成上述模式的最小机制、约束或不变量：

- 去掉人物、品牌和案例后，什么约束仍然存在？
- 哪个机制若不存在，观察到的模式就难以发生？
- 哪些前提来自材料，哪些前提来自外部知识？

把材料直接支持的内容写为“底层原则”。把需要额外前提的内容写为“候选原则（推断）”，并列出前提。材料不足时停止，不制造终极结论。

## Rank and Compress

只保留同时满足多数条件的候选认知：

- 证据强：有具体且足量的原始内容。
- 压缩率高：一条结论解释多条彼此独立的事实。
- 解释力强：回答“为什么”，而不只是重新命名现象。
- 认知增量高：会改变理解、判断或行动。
- 边界清楚：知道结论在哪些条件下可能不成立。

默认输出 3–7 条。合并同义结论，删除仅仅复述话题的条目。不要因为某个观点被重复多次，就自动把它当成最重要的认知。

## Reverse Audit

对每条最终认知执行反向检查：

认知结论 → So What → 抽象模式 → MECE 事实簇 → 关键事实 → 原始内容

逐项检查：

1. 原始内容是否真的出现，而不是只有页码、时间戳或 F 编号？
2. 列出的内容是否足以推出结论中的每个关键限定词？
3. 是否把说话人的主张写成了已经证实的事实？
4. 是否混入材料之外的常识、模型记忆或未经说明的前提？
5. 是否忽略了会改变结论的反例、分歧或样本边界？
6. 如果删掉这些原始内容，结论是否仍像一句放在哪里都成立的套话？若是，重新提炼或删除。

发现断链时，优先缩小结论，而不是补写更多抽象语言。

## Output Contract

默认先给结论，再给可逆推导。不要把工作过程写成冗长流水账。

### 一句话总判断

用一句话表达整份材料最值得保留的认知。材料没有单一主轴时，省略这一节。

### 关键认知

为每条认知使用以下结构：

#### N. 认知结论

用可判断、可反驳的一句话表达，不使用只有主题没有判断的标题。

- 原始内容：
  - F1「最小充分的原话、事实、数字或事件」
  - F2「最小充分的原话、事实、数字或事件」
- 推导链：F1 + F2 → 事实关系或 MECE 共同项 → 抽象模式 → So What
- 底层原则：材料直接支持的机制；若需要额外前提，明确写“候选原则（推断）”。
- 边界：写出关键条件、反例、分歧或不可外推之处。
- 行动含义：仅在任务需要且材料支持时输出。

“原始内容”必须实际呈现内容本身。说话人、时间戳、页码或段落号可以附在片段后帮助查找，但不能单独充当这一栏。

### 认知之间的关系

只有当 3 条以上认知存在明显的因果、层级或张力关系时，用一小段话说明它们如何组成同一个系统。否则省略。

### 未成立的候选

仅在审计型任务中列出看似精彩但证据不足的观点，并说明断链位置。默认省略。

## Adapt by Source Type

- 对话、会议、访谈：保留观点归属和分歧；不要用流畅叙述抹平不同说话人的立场。
- 录音、播客、视频：先处理转写可靠性；让原话片段承担证据作用，时间戳只承担定位作用。
- 综述、报道、研究材料：区分“材料引用的研究结果”和“作者的解释”；除非另行核验，不把二手陈述升级为已验证事实。
- 多份材料：分别维护来源边界。只有在证据兼容时才综合，不把来自 A 的事实写成 B 的主张。

## Common Failure Modes

| Failure | Correction |
|---|---|
| 按出现顺序做缩写 | 先建立事实账本，再全局分组 |
| 用目录式主题代替认知 | 把标题改成可判断、可反驳的结论 |
| 只给时间戳或页码 | 展示足以重建结论的原始内容 |
| 引一段话后直接跳到宏大判断 | 补齐事实关系、抽象模式与 So What |
| 把案例当规律 | 限定为可能性，寻找独立事实或反例 |
| 强行输出第一性原理 | 降级为候选原则或停在洞察层 |
| 抹平冲突以获得整齐结构 | 保留分歧，并缩小结论适用范围 |
| 认知点过多 | 按证据、解释力和认知增量只留前 3–7 条 |

## Final Quality Gate

提交前确认：

- 已阅读完整相关材料，或明确披露覆盖范围。
- 每条认知都展示了原始内容，而非只有定位信息。
- 每条推导链都能正向推出、反向回溯。
- 事实、材料陈述、案例、推断和原则没有混写。
- 第一性原理有机制与前提，不是口号。
- 关键反例与分歧没有被压缩掉。
- 输出比原材料短很多，但没有比证据更确定。
