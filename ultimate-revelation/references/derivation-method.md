# Derivation Method

只在材料很长、来源不止一个、观点冲突明显，或用户要求审计时读取本文。

## 目录

1. 来源准备
2. Pass 1：原子事实账本
3. Pass 2：全局事实簇
4. Pass 3：推导与反向审计
5. 排序与停止条件
6. 来源类型适配

## 1. 来源准备

1. 按自然章节、话题或时间段切块，但不要在单个分块内下全局结论。
2. 保存可定位的来源信息：文件名、作者或说话人、时间戳、页码、表格标题。
3. 保留数字的口径、分母、时间范围和比较基线。
4. 转写或 OCR 不确定时保留原貌并标记，不靠猜测补齐关键名词。
5. 无法覆盖全文时，记录已读与未读范围；局部抽样不能冒充全文结论。

## 2. Pass 1：原子事实账本

为候选事实建立内部编号 F1、F2、F3。每条只承载一个可检查内容：一句原话、一个数字、一个事件或一个明确对比。

记录四类事实：

- **观察事实**：材料可直接支持的事件、行为、数字或对比。
- **材料陈述**：说话人或作者提出的判断。
- **案例**：展示一种可能性，不能自动代表规律。
- **反证/边界**：限制外推、暴露冲突或降低确定性的内容。

每条事实同时保留：谁在说、对象是什么、条件是什么、它与哪条反例冲突。删除寒暄和重复口癖，但不删除少数关键例外。

## 3. Pass 2：全局事实簇

先去重，再选择一个主要维度分组：机制、约束、因果阶段、问题—反应—结果或变化前后。

- 只有任务关注不同立场时才按说话人分组。
- 每条事实只有一个主归属；交叉关系只记录链接，不复制成新证据。
- 类别名写成可判断的关系，例如“执行成本下降后，方向错误被放大”，不用“AI 能力”。
- MECE 是整理工具，不是现实假设；事实重叠时保留重叠，观点冲突时保留冲突。

形成 1–7 个候选事实簇。每个事实簇都必须含有原始内容；没有证据的主题直接删除。

## 4. Pass 3：推导与反向审计

对每个事实簇完成五步。

### 4.1 选择最小证据集

通常选择 2–4 条互补事实。一条决定性事实可以独立成立；同一主张被重复多次仍只算一条证据。

### 4.2 说明事实关系

明确证据之间是并列、对比、递进、因果还是例外。不能说明关系时，不要直接跳到抽象结论。

### 4.3 攀登抽象阶梯

依次询问：

1. 这些事实共有或对立的是什么？
2. 这种关系构成什么稳定模式？
3. 它改变了什么理解、判断或行动？
4. 哪个最小机制若不存在，这个模式就很难发生？

每上升一级都向下检查：它解释了哪些事实；是否抹掉条件或反例；换一组完全不同的事实后仍成立吗？若是，结论可能过于通用。

### 4.4 区分 So What 与 Now What

So What 必须说明认知增量：解释了什么、推翻了什么弱说法、改变了什么判断。避免“这很重要”“这是一种趋势”。

只有材料支持且用户需要时才给 Now What。建议必须能回到材料中的机制和边界。

### 4.5 反向审计

按下列方向逐项回溯：

`认知结论 → So What → 稳定模式 → 事实关系 → 关键事实 → 原始内容`

检查：

1. 原始内容是否真实出现，而非只有定位或内部编号？
2. 证据是否支持结论中的每个限定词？
3. 是否把材料主张升级成已证事实？
4. 是否混入未标明的外部常识或模型记忆？
5. 是否忽略会改变结论的反例、分歧或样本边界？
6. 删掉证据后，结论是否变成放在哪里都成立的套话？

发现断链时，先缩小结论；仍不成立就删除。

## 5. 排序与停止条件

按五项排序：证据强度、压缩率、解释力、认知增量、边界清晰度。

- 只保留能改变理解、判断或行动的条目。
- 证据只支持 1 条，就输出 1 条。
- 没有任何结论超过普通摘要时，明确说明“材料暂未支持更强洞见”，不要制造终极结论。
- 底层机制需要额外前提时，写“候选原则（推断）”并列出前提；材料不足时省略。

## 6. 来源类型适配

- **会议、访谈、对话**：保留观点归属与分歧，避免用流畅叙述抹平立场。
- **录音、播客、视频**：原话承担证据，时间戳只承担定位；先处理转写可靠性。
- **综述、报道、研究材料**：区分研究结果、二手转述和作者解释；未经核验不升级为外部事实。
- **多份材料**：先分别建账本，再判断证据是否兼容；共同出现不等于相互印证。
