# Worked Example

这个虚构例子只用于校准输出形态。

## 原始材料

- 用户 A：“设备到了以后，我不知道先下载 App，还是先连 Wi-Fi。”
- 客服记录：“本月 42% 的咨询发生在初始化和绑定阶段。”
- 可用性测试：“5 名新用户中有 3 名在配网步骤中断；再次使用的老用户均完成核心任务。”
- 产品日志：“完成绑定的用户中，87% 在当天使用了核心功能。”

## 较弱的总结

用户在安装、配网和绑定方面存在问题，需要优化新手引导。

它罗列了主题，但没有说明这些事实共同揭示了什么。

## Ultimate Revelation 输出

### 1. 产品的主要损失不是功能难用，而是用户在体验价值之前就被首次启动流程拦截

- 原始内容：
  - F1 用户 A：“我不知道先下载 App，还是先连 Wi-Fi。”
  - F2 客服记录：“42% 的咨询发生在初始化和绑定阶段。”
  - F3 5 名新用户中有 3 名在配网步骤中断；老用户均完成核心任务。
  - F4 完成绑定的用户中，87% 在当天使用了核心功能。
- 推导链：F1、F2、F3 共同指向首次启动阻塞；F3 与 F4 形成新老用户及绑定前后的对比 → 问题集中在价值到达之前，而非核心功能内部 → 优化重点应从“增加功能说明”转向“缩短首次价值路径”。
- 底层原则：用户只有越过激活门槛才能感知产品价值；发生在首次价值之前的摩擦会直接截断后续价值。
- 边界：样本只有 5 名新用户，不能据此估计全体用户的精确流失率；日志也没有证明绑定流程是所有未使用者的唯一原因。

## 为什么它可反溯

读者不必依赖页码或回看全文，也能从 F1–F4 检查：

1. 阻塞是否集中在首次启动阶段；
2. 核心功能本身是否存在同等强度的失败证据；
3. “价值到达路径”这一抽象是否保留了原始事实；
4. 哪些结论受样本量与因果证据限制。

如果删掉 F3 和 F4，就只能说“初始化存在问题”，不能进一步断言“主要损失发生在体验价值之前”。这就是反向审计对结论强度的约束。
